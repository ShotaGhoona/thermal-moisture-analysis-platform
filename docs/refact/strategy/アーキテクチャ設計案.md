# legacy-julia リファクタリング設計案

## このプロジェクトの本質

```
入力（CSV）→ 物理シミュレーション → 出力（CSV）

本質的にやっていること:
1. モデルを組み立てる（室・壁・開口・気象）
2. 時間を進めながら物理計算を繰り返す
3. 結果を記録する
```

---

## 何が安定していて、何が変わるか

```
安定（めったに変わらない）        変わりやすい（拡張される）
─────────────────────────────────────────────────────────
物理法則                         材料の種類
├── フーリエ則（熱伝導）          ├── コンクリート
├── フィック則（水蒸気拡散）      ├── 断熱材
└── 毛管移動                     └── 新素材...

時間ループの構造                  入出力形式
├── 流量計算                     ├── CSV
├── 収支計算                     ├── Excel
└── 状態更新                     └── 将来的にDB？

基本的な概念                      実行パターン
├── 温度・湿度                   ├── 単一実行
├── 熱流・水分流                 ├── バッチ実行
└── セル・壁・室                 └── 並列実行
```

**設計原則: 安定したものに依存し、変わりやすいものは差し替え可能にする**

## 依存の方向

```
        ┌───────────────────────────────────────────────┐
        │                                               │
        │    runner/       io/                          │  変わりやすい
        │       │      (loader/writer)                  │  （外側）
        │       │           │                           │
        │       └─────┬─────┘                           │
        │             │                                 │
        │             ▼                                 │
        │      ┌──────────────┐                         │
        │      │   modules/   │                         │
        │      │              │                         │
        │      │  solver/ ────┼── materials/            │
        │      │     │        │                         │
        │      │     ▼        │                         │
        │      │  model/      │                         │
        │      │     │        │                         │
        │      │     ▼        │                         │
        │      │  physics/    │  安定（内側）            │
        │      └──────────────┘                         │
        │                                               │
        └───────────────────────────────────────────────┘

ルール:
- 矢印の方向にのみ依存可能
- modules/physics/ は何にも依存しない（純粋な計算）
- modules/model/ は physics/ のみに依存
- modules/solver/ は model/ と physics/ に依存
- modules/materials/ は physics/ に依存（物性計算に物理法則を使う）
- io/, runner/ は modules/ 全体に依存
- io/ と runner/ は互いに依存しない
```

## 各層の役割

### physics/ - 物理法則

変わることがほぼない。純粋な計算関数の集まり。

```julia
# physics/heat.jl
"""熱伝導流束 [W/m²]"""
function heat_flux(λ, T1, T2, dx)
    return -λ * (T2 - T1) / dx
end

"""対流熱伝達流束 [W/m²]"""
function convective_heat_flux(α, T_surface, T_air)
    return α * (T_air - T_surface)
end
```

### model/ - モデルの表現

シミュレーション対象を表す構造体。

```julia
# model/types.jl
struct Cell
    temp::Float64           # 温度 [K]
    miu::Float64            # 水分化学ポテンシャル
    material::Symbol        # 材料名（:concrete, :glass_wool等）
    dx::Float64             # 厚さ
end

struct Wall
    cells::Vector{Cell}
    area::Float64
    # ...
end
```

### solver/ - 計算エンジン

時間ループの中身。model/ の状態を更新する。

```julia
# solver/flux.jl
function calculate_wall_flux!(wall, materials)
    for i in 1:length(wall.cells)-1
        cell1, cell2 = wall.cells[i], wall.cells[i+1]
        λ1 = get_conductivity(materials, cell1)
        λ2 = get_conductivity(materials, cell2)
        # physics/ の関数を使って計算
        q = heat_flux(mean(λ1, λ2), cell1.temp, cell2.temp, ...)
        # ...
    end
end
```

### runner/ - 実行方法

単一実行、バッチ、並列などを切り替え。

```julia
# runner/single.jl
function run_single(config)
    model = load_model(...)
    materials = load_materials()

    while model.time < end_time
        calculate_flux!(model, materials)
        update_state!(model)
        step_time!(model)
    end

    write_results(...)
end

# runner/batch.jl
function run_batch(patterns, config)
    for pattern in patterns
        run_single(pattern)
    end
end

# runner/parallel.jl
function run_parallel(patterns, config)
    Threads.@threads for pattern in patterns
        run_single(pattern)
    end
end
```

## メリット・デメリット

| 観点 | 評価 | 理由 |
|------|:----:|------|
| 依存関係の明確さ | ◎ | 内側→外側の一方向のみ |
| 材料追加の容易さ | ◎ | 1ファイル追加で完結 |
| テスト容易性 | ◎ | physics/ は純粋関数でテスト簡単 |
| 既存コードからの移行 | ○ | 段階的に移行可能 |
| 巨大ファイル分割 | ◎ | 45KB → 複数の小ファイル |
| 入出力形式の変更 | ◎ | io/ のみ変更 |
| 実行方法の変更 | ◎ | runner/ のみ変更 |
| 学習コスト | ○ | シンプルな構造 |
| パフォーマンス | ○ | 層が浅いのでオーバーヘッド小 |

## 移行ステップ

```
Step 1: ディレクトリ構造を作成
├── legacy-julia-refact/ を作成
├── modules/, io/, runner/ を作成
└── io/input/, io/output/ にデータをコピー

Step 2: modules/physics/ を切り出す
├── function/vapour.jl から psychrometrics.jl を作成
├── transfer_in_media.jl から純粋な計算式を抽出
└── 単体テストを書く

Step 3: modules/model/ を整理する
├── 構造体定義を types.jl に集約
├── 不要なフィールドを整理
└── 命名を統一

Step 4: modules/solver/ を分割する
├── transfer_in_media.jl を flux.jl と balance.jl に分割
├── 結露判定を condensation.jl に分離
└── 時間進行を stepper.jl に分離

Step 5: modules/materials/ を整理する
├── interface.jl を作成
├── 31ファイルを整理・統合
└── 材料追加のドキュメントを書く

Step 6: io/ を整理する
├── loader.jl にCSV読み込みをまとめる
├── writer.jl にCSV書き出し・ロギングをまとめる
└── input/output のディレクトリ構造を整理

Step 7: runner/ を整理する
├── single.jl（単一実行）
├── batch.jl（バッチ実行）
├── parallel.jl（並列実行）
└── main.jl でエントリーポイントを統一
```

## まとめ

```
確定した構造:

legacy-julia-refact/
├── main.jl
├── modules/
│   ├── physics/      # 物理法則（最も安定）
│   ├── model/        # 型定義
│   ├── solver/       # 計算エンジン
│   └── materials/    # 材料物性
├── io/
│   ├── input/        # 入力データ（1d, 3d, 3d-network, constant）
│   ├── output/       # 出力データ
│   ├── loader.jl     # 読み込みコード
│   └── writer.jl     # 書き出しコード
└── runner/           # 実行方法（single, batch, parallel）

設計の核心:

1. 「安定しているもの」を内側に置く
   → modules/physics/, modules/model/

2. 「変わりやすいもの」を外側に置く
   → modules/materials/, io/, runner/

3. 依存は内側へのみ向ける
   → 外側を変えても内側に影響しない

4. データとコードを近くに置く
   → io/ にデータファイルとloader/writerを同居
```
